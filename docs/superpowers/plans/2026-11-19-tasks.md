# Tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add first-class tasks to fishy. A task has a stable id, links to many bones and
has configurable states. It can be referenced from log entries and created by converting
existing checkboxes. Tasks are visible per bone and in a sortable, editable all-tasks
window, and can be exported to CSV.

**Architecture:** Same single-direction flow as the rest of the app:
UI → `ProjectDocument` command (`QUndoCommand`) → `Repository` transaction → document
caches and signals → views. The tasks-related rules that don't depend on Qt
(open/overdue/toggle/roll-up/sort) live in `fishy/domain/tasks.py`. The text rules
(rendering references, converting checkboxes) live in `fishy/markdown_render.py` and
`fishy/task_markup.py`, with no Qt dependency.

**Tech Stack:** Python 3.15, PySide6 6.12 (Qt Widgets), sqlite3, markdown-it-py, pytest +
pytest-qt, ruff.

**Spec:** `docs/superpowers/specs/2026-11-19-tasks-design.md` (section refs below are §n.n
of the spec).

## Global Constraints

- Schema v3 is `fishy/storage/schema/003_tasks.sql`. The existing runner applies it and
  writes `.bak-v2` automatically.
- `task` uses `INTEGER PRIMARY KEY AUTOINCREMENT`, so ids are never reused.
- `Repository` stays the only code that runs SQL. Every user edit is a `ProjectDocument`
  command (undoable, written through immediately) and appends a `history` row with the
  entity `task`, `task_state` or `task_link`.
- `fishy/markdown_render.py`, `fishy/task_markup.py` and `fishy/domain/*` import no Qt.
- Raw HTML stays disabled in markdown. Task markup is produced by post-processing the
  rendered output, never by allowing HTML input.
- Default task states, in this order: To do ☐ `#90a4ae` not_started (default),
  In progress ◐ `#1e88e5` active, Blocked ⊘ `#e53935` blocked, Done ☑ `#43a047` done.
- "Open" means the state's role ≠ `done`. "Overdue" means open and `due_date` is earlier
  than **today's local date** (due today is not overdue).
- Toggle: open → first `done`-role state by `sort_order`; done → default state.
  Cycle (Ctrl+Shift+Enter): next state by `sort_order`, wrapping.
- At least one task state must have the `done` role. The error message is
  `"At least one task state must count as done."`
- Tasks window shortcut: **Ctrl+Shift+T** (Ctrl+T is Timeline). *Hide done* is on by
  default.
- The per-bone *Show done* toggle is the app setting `tasks/show_done` (default `False`).
- CSV: UTF-8 **with BOM**, CRLF, stdlib `csv`. Columns, in this order: ID, State, Done,
  Title, Bones, Assignee, Due, Critical, Overdue, Notes, Created, Created by, Updated,
  Updated by.
- Ruff: line length 100, rules E F I UP B. Run `uv run ruff check .` before each commit.

## Review Focus

Inputs the spec implies but no task's tests would otherwise exercise. Each line's test is
added to the task named.

1. **Converting a checkbox whose text contains markdown, a `[[bone:N]]`, trailing spaces
   or is nested under another list item.** Only that line changes, the indentation and
   bullet stay, and the title keeps the text verbatim. → Task 5
   (`test_convert_preserves_odd_lines`).
2. **A blank title (in the window, the editor or the per-bone list).** It's refused with
   `RuleError("A task needs a title.")` and the old title is kept. → Task 2
   (`test_blank_title_rejected`).
3. **Deleting a bone whose tasks are also linked elsewhere, then undo/redo several
   times.** The links are restored exactly, with no primary-key conflicts and no
   duplicate rows. → Task 3 (`test_delete_bone_undo_redo_cycles_links`).
4. **A due date of today, judged by the local date and not UTC.** Not overdue. → Task 1
   (`test_due_today_not_overdue`).
5. **Notes containing commas, quotes and newlines; titles containing glyphs and
   accents.** The CSV reads back identically with `csv.reader`, and Excel sees UTF-8
   (BOM present). → Task 11 (`test_csv_round_trips_awkward_text`).

**Interfaces:**
- Produces (in `fishy.domain`):
  - `@dataclass TaskState(id: int, name: str, color: str, symbol: str, role: StatusRole = StatusRole.NOT_STARTED, sort_order: int = 0, is_default: bool = False)`
  - `@dataclass Task(id: int, title: str, state_id: int, notes: str = "", assignee: str | None = None, due_date: str | None = None, critical: bool = False, bone_ids: list[int] = field(default_factory=list), created_at: str = "", updated_at: str = "", created_by: int | None = None, updated_by: int | None = None)`
- Produces (in `fishy.domain.tasks`), where `states: dict[int, TaskState]`:
  - `is_done(task: Task, states) -> bool`
  - `is_overdue(task: Task, states, today: date) -> bool`
  - `default_state_id(states) -> int` and `done_state_id(states) -> int` (first `done` role by `sort_order`)
  - `toggle_target(task: Task, states) -> int`
  - `next_state_id(task: Task, states) -> int`
  - `task_sort_key(task: Task, states) -> tuple` = `(done, due is None, due or "", id)`
  - `task_groups(tree: BoneTree, links: dict[int, set[int]], bone_id: int) -> list[tuple[int, list[int]]]` (§4.5). `links` maps bone id → task ids. The first group is `(bone_id, direct ids)`. Categories then get one group per **child** cause in tree order, holding the ids linked anywhere in that cause's subtree that haven't been listed yet. Empty groups are dropped. Ids within a group are ascending; the caller sorts them for display.
  - `rolled_task_ids(tree, links, bone_id) -> list[int]` (all ids across `task_groups`, each once)
  - `distinct_assignees(tasks: Iterable[Task]) -> list[str]` (trimmed, deduplicated case-insensitively keeping the first spelling seen, sorted case-insensitively)
  - `number_sort_key(number: str) -> tuple[int, ...]` (`"1.10"` → `(1, 10)`; `""` → `(10**9,)`)
